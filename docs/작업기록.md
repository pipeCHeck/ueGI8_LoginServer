## 2. 확정된 설계 결정

- **인증 실패도 HTTP 200 + `{"result": false}`** — 401/400을 쓰지 않는다. C++ 클라이언트가 "서버가 답했는데 인증이 틀렸다"와 "서버에 닿지 못했다"를 깔끔히 구분하기 위해서다.
- **비밀번호 평문 저장** — 학습용 프로젝트의 의도된 결정. 해싱을 도입하지 않는다.
- **DB 스키마 변경 없음** — `user_id`에 이미 `user_id_UNIQUE` 인덱스가 있어 중복 가입은 DB가 막는다.
- **회원가입 입력은 `user_id`, `passwd` 둘뿐** — 서버가 `nickname = user_id`, `level = 1`을 채운다. 닉네임 입력칸을 만들지 않는다.
- **가입 후 자동 로그인 안 함** — 가입과 로그인은 분리된 동작이다.
- **포트 8080 고정** — 클라이언트 URL은 `http://{ServerIP}:8080`. (원래 8000이었으나 언리얼 MCP 플러그인이 8000을 점유해 변경) ServerIP는 Title 화면의 기존 입력칸을 재사용한다.
- **pytest 미사용** — 검증은 `/docs`와 수동 확인으로 한다.
- **가상환경은 `Server/.venv`에만** — 전역 설치 금지. git에서 제외.

### 응답 계약

```json
{ "result": true, "message": "", "idx": 1, "nickname": "junios", "level": 1 }
```

| 상황 | HTTP | result | message |
|---|---|---|---|
| 성공 | 200 | `true` | `""` |
| 아이디 중복 | 200 | `false` | `이미 존재하는 아이디입니다` |
| 로그인 실패 | 200 | `false` | `아이디 또는 비밀번호가 올바르지 않습니다` |
| 빈 값 | 422 | — | Pydantic `min_length=1`이 거부 |
| 그 밖의 비정상 | 4xx/5xx | — | 클라이언트가 `요청을 처리할 수 없습니다 (코드 N)` 표시 |

### 검증 결과 (Task 1~3, 서버)

- MySQL 접속 성공, `member` 0행에서 시작
- `user_id_UNIQUE` 인덱스 확인 (`Non_unique: 0`)
- 가입 성공 → `{"result":true,"idx":1,"nickname":"junios","level":1}`
- 같은 아이디 재가입 → `{"result":false,"message":"이미 존재하는 아이디입니다"}`, **행 수 1 유지**
- 빈 `user_id` → HTTP 422
- 정상 로그인 → `{"result":true,"idx":1,"nickname":"junios","level":1}`, HTTP 200
- 틀린 비밀번호 / 없는 아이디 → **동일한 응답 본문**, HTTP 200 (401 아님)
- 리뷰에서 SQL 파라미터 바인딩(`%s`)과 커넥션 `finally` 정리 확인 — 인젝션·누수 없음

## 4. 진행 중 내린 판정

계획대로 갈 수 없는 지점에서 내린 결정과 그 근거다.

| | 판정 | 근거 |
|---|---|---|
| A | uvicorn을 백그라운드로 띄우고 `/docs` 대신 `curl`로 검증 | 자동화 실행 주체에게 포그라운드 서버는 블로킹이다. `/docs`는 같은 HTTP 표면을 사람이 보기 좋게 감싼 것일 뿐이라 검증 대상이 동일하다. |
| B | UE 컴파일 검증을 Visual Studio 대신 `Build.bat` CLI로 | GUI를 쓸 수 없는 환경. 실패하면 그 자리에서 드러난다. |
| C | **Task 7은 위임하지 않는다** | 언리얼 에디터 위젯 배치와 PIE 실행은 사람만 할 수 있다. 수동 체크리스트로 넘긴다. |
| D·F | MySQL 비밀번호는 추측하지 않고 사람이 직접 채운다 | 자격증명 추측 금지. 사용자가 `Server/db.py`에 직접 입력했고, 이후 덮어쓰지 않는다. |
| E | `.gitignore`에 `__pycache__/` 추가 | 계획 누락. `Server/.venv/`만으로는 `.pyc`가 추적된다. |
| G | `cryptography`를 requirements.txt에 추가 | MySQL 8의 `caching_sha2_password` 인증에 PyMySQL이 요구한다. 대안인 "계정을 `mysql_native_password`로 변경"은 DB 서버 설정을 건드리고 MySQL 8.4+에서 해당 플러그인이 제거되어 수명이 짧다. |
| H | 언리얼 에디터가 켜져 있으면 빌드를 멈추고 사람에게 묻는다 | 에디터가 DLL을 잠가 빌드가 실패한다. 그렇다고 에디터를 강제 종료하면 저장 안 된 작업이 날아간다. 되돌릴 수 없는 손실이라 스스로 판정하지 않는다. **Task 6에서 실제로 발동했다.** |
| I | Task 5 리뷰만 상위 모델로 돌린다 | 나머지는 기계적 diff지만 `WebApiSubsystem`은 비동기 콜백 수명, 임시 문자열 수명, 에러 분기 순서가 얽혀 있다. 컴파일은 통과해도 레벨 전환 중 응답이 도착하면 크래시하는 종류라 빌드가 잡아주지 못한다. |

E와 G는 모두 계획서 자체의 결함이었고, 실행 중 드러나 메웠다. H는 사람에게 물어 해소했다 — 에디터를 닫아주신 뒤 빌드가 통과했다.

### 미결 사항

- `LobbyWidgetBase.h`에 `meta = (WidgetBind)` 오타가 **6곳** 남아 있다 (`StartButton`, `ChatButton`, `ChatInput`, `LeftTimeText`, `ConnectCountText`, `ChatScrollBox`). 이번 범위 밖이라 손대지 않았다. 고치면 `WBP_Lobby`에 같은 이름의 위젯이 실제로 있어야 컴파일되므로, 별도 작업으로 다룰 것.
- `TitleWidgetBase`의 `StartServerButton`은 `BindWidget`이 아니라 `GetWidgetFromName`으로 찾는다. 그래서 이 버튼만 `WBP_Title`에 없어도 블루프린트 컴파일이 통과하고, 대신 런타임에 조용히 동작하지 않는다. 나머지 4개는 이름이 틀리면 컴파일 에러로 바로 드러난다. 의도된 것인지 확인 필요.
- 에디터에서 `ModelContextProtocol`, `EditorToolset` 플러그인을 켠 `.uproject` 변경과 그에 따라 생긴 `.codex/`, `.cursor/`, `.gemini/`, `.mcp.json`, `.vscode/` 는 이번 작업과 무관해 커밋하지 않았다. 그대로 남아 있다.

## 8. Task 7 — 사람이 직접 할 일

언리얼 에디터 위젯 배치와 PIE 실행은 자동화할 수 없다. Task 1~6이 끝나면 아래를 순서대로 확인한다.

**사전 준비:** 서버를 켜둔다.

```
C:\Work\L20260713_Day03\Server\run.bat
```

`run.bat`은 어느 위치에서 실행해도 `Server/`로 이동해 venv 파이썬으로 8080 포트에 서버를 띄운다. 멈출 때는 `Ctrl+C`.

### 8.1 위젯 배치

`Content/Blueprints/Title/UI/WBP_Title`을 열고 디자이너에 아래를 추가한다. **이름은 대소문자까지 정확히** 맞춰야 한다.

| 타입 | 이름 |
|---|---|
| Button | `LoginButton` |
| Button | `SignUpButton` |
| Text | `InfoText` |

버튼 안에 라벨용 Text를 넣는 경우 그 Text의 이름은 아무거나 상관없다. 맞춰야 하는 건 Button 자체다.

### 8.2 기존 위젯 이름 확인

`meta = (BindWidget)` 지정자를 쓰므로 아래 4개가 `WBP_Title`에 **같은 이름으로 존재해야** 블루프린트가 컴파일된다.

`ConnectServerButton`, `UserID`, `Password`, `ServerIP`

`A required widget binding "X" of type Y was not found` 에러가 나면 해당 위젯 이름이 다른 것이다. 디자이너에서 이름을 고친다.

> `StartServerButton`은 예외다. 이 프로퍼티만 `BindWidget`이 아니라 `GetWidgetFromName`으로 찾으므로 없어도 컴파일은 된다. 다만 없으면 버튼이 동작하지 않는다.
