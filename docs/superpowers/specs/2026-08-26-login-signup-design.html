엔드포인트

엔드포인트 2개, 요청·응답 스키마는 양쪽이 동일합니다.

POST /signup                          POST /login
{ "user_id": "junios",                { "user_id": "junios",
  "passwd":  "1234" }                   "passwd":  "1234" }
// 성공
{ "result": true,  "message": "",                         "idx": 1, "nickname": "junios", "level": 1 }

// 실패 (가입: 아이디 중복 / 로그인: 아이디·비번 불일치)
{ "result": false, "message": "이미 존재하는 아이디입니다", "idx": 0, "nickname": "",       "level": 0 }

설계 판단 — 인증 실패도 HTTP 200으로 응답합니다.

401/400을 쓰지 않는 이유는, 로그인 실패가 서버가 정상적으로 처리한 결과이지 프로토콜 오류가 아니기 때문입니다. 이렇게 하면 C++ 쪽 분기가 두 갈래로 단순해집니다.

  • 서버가 답을 줬다 (200) → result 값으로 성공/실패 판정
  • 서버가 답을 못 줬다 (연결 실패 · 5xx) → 서버 장애로 안내

덕분에 사용자에게 "비밀번호가 틀렸습니다"와 "서버에 연결할 수 없습니다"를 정확히 구분해 보여줄 수 있습니다.

전제

  • 웹서버 포트는 8080 고정 (언리얼 MCP 플러그인이 8000을 점유해 2026-08-26에 8000에서 변경). ServerIP 칸에 포트까지 적는 경우(127.0.0.1:7777)는 다루지 않습니다.
  • 회원가입 중복 검사는 SELECT 후 INSERT가 아니라 user_id에 UNIQUE 제약을 걸고 IntegrityError를 잡는 방식입니다. 동시에 같은 아이디로 요청이 들어와도 중복 행이 생기지 않습니다.

확인 완료 (2026-08-26) — seul.member.user_id에 UNIQUE 인덱스가 이미 존재합니다. 스키마 변경 없이 진행합니다.

2. 구현 구조 검토 요청

2-1. 파이썬 서버

Server/

  main.py            # FastAPI 앱, /signup /login 라우트, Pydantic 모델

환경 준비 — 전역에 이미 있는 pydantic·uvicorn·httpx도 가상환경 안에 다시 설치됩니다(의도된 격리).

.gitignore에 Server/.venv/ 한 줄을 추가합니다.

엔드포인트가 2개뿐이라 main.py 하나로도 충분하지만, DB 접속 정보만 db.py로 분리합니다. PC마다 바뀌는 값이 한 파일에 모여 있어야 다른 환경에서 실행할 때 고칠 곳이 명확합니다. Pydantic 모델은 클래스 2개뿐이라 main.py에 그대로 둡니다 — 별도 models.py는 지금 규모에서 파일만 늘립니다.

# db.py
DB_CONFIG = dict(host="127.0.0.1", port=3306, user="root",
                 password="<비밀번호>", db="seul", charset="utf8mb4")

def get_connection():
    return pymysql.connect(**DB_CONFIG, cursorclass=pymysql.cursors.DictCursor)
# main.py 골자
class AuthRequest(BaseModel):
    user_id: str = Field(min_length=1)
    passwd:  str = Field(min_length=1)

class AuthResponse(BaseModel):
    result: bool
    message: str = ""
    idx: int = 0
    nickname: str = ""
    level: int = 0

@app.post("/signup", response_model=AuthResponse)   # INSERT, IntegrityError → 중복
@app.post("/login",  response_model=AuthResponse)   # SELECT idx, nickname, level
  • 커넥션: 요청마다 with로 열고 닫습니다. 이 규모에서 커넥션 풀은 불필요합니다.
  • 가입: INSERT INTO member (user_id, passwd, nickname, level) VALUES (%s, %s, %s, 1) — nickname에 user_id를 그대로 넣고, cursor.lastrowid를 idx로 반환합니다.
  • 로그인: SELECT idx, nickname, level FROM member WHERE user_id = %s AND passwd = %s — 결과가 없으면 실패.
  • 모든 SQL은 파라미터 바인딩(%s)을 씁니다. 문자열 포매팅으로 조립하지 않습니다.

바인딩 지정자 오타 — 수정 완료 (커밋 d568bf4)

TitleWidgetBase.h의 UserID, Password, ServerIP, ConnectServerButton에 붙어 있던 meta = (WidgetBind)는 언리얼이 인식하는 지정자가 아니어서 해당 위젯들이 바인딩되지 않은 채 남아 있었습니다. 정식 지정자인 meta = (BindWidget)으로 고쳤습니다.

확인이 필요한 부작용 — BindWidget은 이름이 일치하는 위젯이 블루프린트에 반드시 있어야 합니다. WBP_Title에 UserID, Password, ServerIP, ConnectServerButton과 정확히 같은 이름의 위젯이 없으면 이제 블루프린트 컴파일 에러가 납니다. 런타임에 조용히 null이 되던 것보다 낫지만, 이름이 다르면 디자이너에서 맞춰줘야 합니다.

신규 위젯(LoginButton, SignUpButton, InfoText)도 같은 BindWidget 방식으로 통일합니다.

미결 — LobbyWidgetBase.h에 같은 오타 6개

StartButton, ChatButton, ChatInput, LeftTimeText, ConnectCountText, ChatScrollBox가 모두 meta = (WidgetBind)이며, GetWidgetFromName 폴백 없이 전부 if (X) 가드로만 감싸져 있습니다.

이번 작업 범위 밖이고, 잘못 고치면 WBP_Lobby 컴파일이 깨질 수 있어 건드리지 않았습니다. 별도 작업으로 다룰지 결정 필요.

3. 에러 처리와 검증 검토 요청

3-1. 에러 대응표

상황서버 응답클라이언트 표시
아이디 중복 (가입)200 / result:false이미 존재하는 아이디입니다
아이디·비번 불일치 (로그인)200 / result:false아이디 또는 비밀번호가 올바르지 않습니다
아이디/비번 빈 값요청 자체를 보내지 않음
(서버도 min_length=1로 방어 → 422)		아이디와 비밀번호를 입력해 주세요
그 밖의 비정상 응답 (422 · 500 등)200이 아닌 모든 코드요청을 처리할 수 없습니다 (코드 N)
서버 미실행 / 주소 오류—서버에 연결할 수 없습니다
응답 JSON 파싱 실패—응답을 해석할 수 없습니다

빈 입력을 클라이언트에서 한 번, 서버에서 또 한 번 막는 것은 중복이 아닙니다. 클라이언트 검사는 불필요한 왕복을 줄이는 편의이고, 서버 검사는 신뢰 경계에서의 방어입니다.

3-2. 검증 순서

서버를 먼저 완성해 단독으로 통과시킨 뒤 C++에 손을 댑니다. 두 쪽이 동시에 안 될 때 원인을 찾느라 헤매는 상황을 막기 위해서입니다.

#단계검증 방법
1uvicorn main:app --reload 실행 후 /docs에서 /signup 호출Workbench에서 member 행 1개, nickname = user_id, level = 1 확인
2같은 아이디로 /signup 재호출result:false + 행 개수가 여전히 1
3/login 정상 / 틀린 비번각각 result:true / result:false
4UE 실행 후 로그인 전 StartServer 클릭레벨 이동이 일어나지 않음
5틀린 비번으로 로그인실패 메시지 표시, 두 버튼 비활성 유지
6정상 로그인junios (Lv.1) 표시, 두 버튼 활성, StartServer 정상 동작
7서버를 끈 상태로 로그인"서버에 연결할 수 없습니다" 표시 (멈추거나 크래시하지 않음)

1~3번은 /docs Swagger UI에서, 4~7번은 UE 에디터 PIE에서 확인합니다. 각 단계는 이전 단계가 통과한 뒤에만 진행합니다.
